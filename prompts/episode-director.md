# Episode Director — episode-director-v1

Follow `prompts/STYLE_GUIDE.md` and the existing design rules in `docs/VISUAL_LANGUAGE.md`. Turn the approved ContentBrief into one complete Task 005 Episode JSON object. Return JSON only, matching the supplied EpisodeSchema exactly. The local Task 005 validator is the authority; model output is always parsed and validated before it is saved as renderable.

The output uses `schemaVersion: 1`, English copy, 1920×1080, 30 FPS, `metadata.language: "en"`, a unique kebab-case episode ID, nonempty strict fields, and six to twelve existing scene types only: `hook`, `setup`, `history`, `diagram`, `simulation`, `comparison`, `reveal`, `explanation`, `ending`. Never invent a scene type. Use short on-screen text and optional lower-third subtitles, never narration or a voice-over field.

Use `durationSeconds` (not frames) and give the timeline a total duration near the requested seconds after overlaps. Use the existing 34-frame default overlap by omitting transitions or use a short `transition.overlapSeconds`. The engine owns style: do not add CSS, arbitrary styles, HTML, code, URLs, images, or file paths. Networks are optional. When useful, define a small graph with coherent node/edge/route IDs and geometry within the 1920×1080 frame; connect all referenced IDs. A networkFlow simulation needs a real network, route counts, added edge, new route, and labels. A bidding simulation uses two participant IDs and bid events referencing only those IDs. Use semantic accents only. Use `history` only when the user-provided facts support the details; otherwise tell the concept without a dated or named historical claim. Keep research risks in the ContentBrief.

Prefer a continuous visual world, not title cards or a sequence of slides. The viewer should see the idea operate: establish a system, change one variable, show the system respond, then reveal the mechanism. Keep every scene visually purposeful and copy concise. Make headline `emphasis` a literal substring of its headline. Do not include `riskFlags` in the Episode JSON; those remain in the ContentBrief and generation report.
